# Deploying Curtis Image Studio to Render

## One-time setup

1. Create a new Render account or log in at https://render.com
2. Create a new **Blueprint** from this repository (New → Blueprint → connect your repo)
3. Render reads `render.yaml` and creates one service:
   - **curtis-image-studio** — the web service (Node API + React frontend)

The project pins Node.js 22.16.0 and pnpm 10.26.1 so Render uses a compatible
runtime and package manager.

## Environment variables to set manually in Render dashboard

After Blueprint creation, go to the **curtis-image-studio** web service → **Environment** and fill in:

| Variable | Description |
|----------|-------------|
| `PUBLIC_APP_URL` | The full HTTPS URL of your deployed web service, e.g. `https://curtis-image-studio.onrender.com` — required for Instagram publish and A2E video rendering |
| `DATABASE_URL` | PostgreSQL connection string for the Studio Album. Required for generated scenes to persist. |
| `STUDIO_ACCESS_PASSWORD` | A strong, unique operator password. Required to unlock and protect the private Studio Album in production. |
| `AI_INTEGRATIONS_OPENAI_API_KEY` | OpenAI API key (from your Replit managed integration or OpenAI dashboard) |
| `AI_INTEGRATIONS_OPENAI_BASE_URL` | OpenAI base URL (e.g. `https://api.openai.com/v1`) |
| `A2E_API_KEY` | A2E image-to-video API key |
| `COMPOSIO_API_KEY` | Composio API key for Instagram publishing |
| `NVIDIA_API_KEY` | NVIDIA NIM API key — enables ultra-realistic cinematic prompt direction |

`SESSION_SECRET` is auto-generated by Render (`generateValue: true`).

## Database migrations

The Render Blueprint runs `pnpm --filter @workspace/db run migrate` as its
pre-deploy command. It applies only versioned Drizzle migrations from
`lib/db/drizzle/` after the build succeeds and before the new API starts.
Use a fresh PostgreSQL database for the initial deployment, then keep
`DATABASE_URL` connected to that same database for subsequent deploys.

## Port binding

The web service listens on port `10000` (Render's default). This is set via the `PORT` env var in `render.yaml`.

## Free-tier availability

Render does not support Cron Jobs on the free plan, so this Blueprint creates no
keep-alive job. Free web services may spin down after inactivity and wake on the
next request. This deployment supports on-demand generation and publishing; it
does not promise unattended daily scheduling or automatic publishing. Use a paid
always-on service and a scheduled worker before enabling those workflows.

## Re-deploying

Push to your connected Git branch. Render auto-deploys on every push.
